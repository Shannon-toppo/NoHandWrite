# NoHandWrite 処理フローと技術まとめ

少量の手書きサンプルから書き手の字体を学習し、補正した文字と AI 生成した文字を組み合わせて、ペンプロッター用のデータまで出力するローカル Web アプリ。全パイプラインがストローク(筆順付き点列)ベースで、画像は SDT のスタイル参照にしか使わない。

## 全体構成

```
web/                ブラウザUI(素のJS、ビルドなし)
  index.html        ✏️ 入力     お題文字を手書きで入力
  library.html      📚 ライブラリ 重ね描き+平均文字の確認、文字リセット
  generate.html     🖋 生成      テキスト→筆跡レンダリング、SVG/G-codeダウンロード
  typeset.html      🖨 組版      mm指定のページレイアウト+プレビュー+エクスポート
server/main.py      FastAPI(保存・補正・生成・組版・エクスポートAPI+静的配信)
core/nohandwrite/   ロジック本体(下記フローの各段)
third_party/SDT/    SDT本体(vendored, MIT)+学習済み日本語モデル(git管理外)
data/<writer>/      1文字1ファイルのJSON(git管理外)
```

サーバは `uv run uvicorn server.main:app --host 0.0.0.0 --port 8765`。iPad の Safari から LAN 経由で開けば Apple Pencil の筆圧つきで入力できる。

## 処理フロー

```
✏️ 入力(Pointer Events, 筆圧つき)
   │  POST /api/samples
   ▼
data/<writer>/uXXXX.json   ← 元座標のまま無劣化保存(store.py)
   │
   ├─ 書いた文字 ──→ フーリエ級数平均で補正(fourier.py / beautify.py)
   │                     │
   ├─ 書いていない文字 → SDT で生成(generate/sdt_adapter.py)
   │                     │
   ▼                     ▼
   グリフメトリクス表で共通のサイズ・位置に配置(metrics.py)
   │
   ▼
   ゆらぎ付与: 1回描画するたびに微小変形(variation.py)
   │
   ▼
   組版: mm単位でページにレイアウト(export/layout.py)
   │
   ├──→ 単線SVG(export/svg.py)
   └──→ G-code(export/gcode.py)
```

### 1. 入力と保存

- ブラウザの canvas 上で座標 (x, y)、ペンダウンからの時刻 t (ms)、筆圧 p (0–1) を記録する。ストロークは (N, 4) の float 配列。
- `data/<書き手ID>/uXXXX.json` に 1 文字 1 ファイルで追記保存。座標変換は一切かけず元のキャンバス座標のまま持つので、正規化方式を後から変えてもデータ移行が要らない。
- お題セット(スタイル学習+英数字の 87 字など)は `server/prompts.py`。同じ文字を複数回書くと平均文字の材料になる。

### 2. 補正: フーリエ級数平均(EC2014「平均文字は美しい」)

`core/nohandwrite/fourier.py`。中村らの手法の実装で、各ストロークを平面曲線 (x, y) = (f1(t), f2(t)) とみなしてフーリエ級数展開し、複数回書いた同じ文字の係数を平均すると、震えが消えて字体だけが残る。

実装上のポイント:

- **偶拡張(コサイン級数)**: ペンストロークは開曲線なので、そのまま 2π 周期とみなすと端点にジャンプができてギブス現象が出る。[0, π] にパラメータ化して [-π, 0] に鏡映することで周期拡張が連続になり、コサイン項だけで表せる。
- **等弧長リサンプリング**: 解析前に 256 点へ等弧長で打ち直し、離散和が論文の積分を近似するようにしている。
- **自動打ち切り**: 次数 n と n+1 の再構成の平均距離が閾値以下、を 2 次数連続で満たした点で打ち切る(奇数次しか成分がないスペクトルで 1 回の小差分に騙されないため)。
- **逆向きストロークの補正**: サンプル間で書き方向が逆のストロークは端点距離で検出してパラメータを反転してから平均する。
- **画数フィルタ**: 画数が多数派と違うサンプル(書き損じ)は平均から除外(`filter_matching_samples`)。
- サンプルが 1 つしかない文字は平均の代わりに単発の平滑化(`smooth_stroke`)で対応する。

### 3. 生成: SDT(CVPR 2023)

`core/nohandwrite/generate/sdt_adapter.py`。書いていない文字は SDT (Style Disentangled Transformer) の日本語学習済みモデル(TUAT HANDS 由来、研究・個人利用のみ)で生成する。

- スタイル参照は、書き手のサンプル数が多い文字から最大 15 字を選び、補正済みストロークを 64×64 のグレースケール画像(4 倍スーパーサンプリング+LANCZOS 縮小)にレンダリングして渡す。
- コンテンツ側は `Japanese_content.pkl` の字形辞書。辞書にない文字は「生成不可」として空白扱いになる。
- 出力は (dx, dy, s1, s2, s3) の差分列で、累積和+ペンアップフラグでストローク列に戻す。
- デバイスは CUDA → MPS → CPU の順で自動選択。vendored の `gmm.py` に `.cuda()` 決め打ちをデバイス非依存化する 2 行パッチを当ててあり、Mac の MPS で動作確認済み。
- モデルは初回リクエスト時に遅延ロード。モデル一式がなくても補正・入力だけで動く。

### 4. サイズ正規化と配置: グリフメトリクス

`core/nohandwrite/metrics.py`。筆跡由来と SDT 由来でサイズの出どころが違う(入力欄への書き方依存 vs 字面いっぱい)問題を、全グリフを一旦 bbox 正規化してからルール表で縮小・アンカー配置する方式で解決した(README の案 B)。

- 文字種デフォルト: 漢字 0.90 > かな 0.82 > 英数字 0.72 > 記号 0.70。
- 個別文字の上書き: 小書き仮名(左下寄せ 0.62)、句読点(左下)、括弧、英小文字の x-height / アセンダー / ディセンダー(ベースライン約 0.88 相当)など。
- 例外はライブラリ画面の平均文字(赤太線)だけで、生サンプルに重ねる必要があるため field-relative(`beautify(place=False)`)のまま描く。

### 5. ゆらぎ(per-instance variation)

`core/nohandwrite/variation.py`。補正も生成も決定的なので、同じ文字が 2 回出るとピクセル一致して機械っぽく見える。描画のたびに、文字全体への微小アフィン変換(回転 SD 0.8°、スケール、平行移動)+ストロークごとの低周波ウォブル(3 倍音まで)をかけて、字形は同じで筆の運びだけ違う実体を作る。強さはひらがな / カタカナ / 漢字 / 英数字 / 記号の文字種別に 0–3 で指定できる。

### 6. 組版

`core/nohandwrite/export/layout.py`。文章を mm 単位でページに配置する。プレビュー(`POST /api/typeset`)とエクスポートが同じレイアウトコードを共有する。

- 文字サイズ、文字間(負値で詰め組み可)、行間、行幅、余白を mm で指定。A4 / B5 の用紙プリセットあり。
- **可変幅字送り**(デフォルト): 各グリフのインク幅で送る。等幅はオプション。ASCII スペースは 0.4 セル。
- **縦書きモード**: 上から下・右から左の段組み。長音や括弧類は 90° 回転、句読点と小書き仮名は右上寄せに再アンカー(JIS 縦書き字形の簡易版)。
- 行下線ガイドをプレビューにだけ描く(エクスポートには含めない)。
- 配置後に RDP(Ramer–Douglas–Peucker、許容誤差 0.05 mm)で点列を間引く。

### 7. 出力

- **単線 SVG**(`export/svg.py`): 1 ストローク = 1 `<path>`、mm の viewBox。パスが筆順どおりに並ぶので、文書順に描くプロッタードライバなら筆順が保たれる。
- **G-code**(`export/gcode.py`): mm 単位・絶対座標。デフォルトは Z 軸ペン上下(GRBL 系)、サーボ式は `pen_up_cmd` / `pen_down_cmd` を差し替える。送り速度(描画 / 移動)と Y 軸反転も指定可。

## 使用技術

| 領域 | 技術 |
|---|---|
| 補正 | フーリエ級数平均(EC2014)、偶拡張、等弧長リサンプリング、自動打ち切り |
| 生成 | SDT (CVPR 2023) 日本語学習済みモデル、PyTorch(CUDA / MPS / CPU 自動選択) |
| 配置 | bbox 正規化+ルールベースのグリフメトリクス表 |
| ゆらぎ | ランダム微小アフィン+低周波ウォブル |
| 組版 | 可変幅字送り、縦書き字形調整、RDP 簡略化 |
| 出力 | 単線 SVG、G-code(GRBL / サーボ両対応) |
| サーバ | FastAPI + Pydantic、静的配信、ETag ベースのキャッシュ制御 |
| フロント | 素の JS(ビルドなし)、Pointer Events(Apple Pencil 筆圧対応) |
| 開発 | uv、pytest(22 件 green)、Python 3.11+ |

## 現状と次の候補

M4 まで完了。データ入力から補正・生成・組版・プロッター用出力までは一通り通る。残っているのは M5(ファインチューニング、筆圧→線幅、プロッター実機)と iPad 実機確認。

優先度をつけるならこの順だと思う:

1. **筆圧→線幅**(手をつけやすく効果が大きい)。筆圧 p はすでに全サンプルに保存済みで、リサンプリングも 4 列全部を補間しているのに、出力では捨てている。SVG なら筆圧に応じて幅を変えたアウトラインパス(または線分ごとの stroke-width)、プロッターなら Z 深さや速度への変調で表現できる。フーリエ平均に p 列も乗せれば平均文字にも筆圧が残る。
2. **禁則処理**。いまの `layout_text` は行末あふれで機械的に折り返すので、行頭に「。」「」」が来る。行頭禁則・行末禁則(追い出し / ぶら下げ)を入れると組版の見た目が一段上がる。実装は layout.py に禁則文字集合と折り返し判定を足すだけで済むはず。
3. **プロッター実機検証**。G-code は未検証のまま仕様で書いてある部分(送り速度の妥当値、ペンサーボのタイミング)があり、実機で1枚描けば一気に確度が上がる。ストローク描画順の移動距離最適化(近い文字から描く)も実機で効く。
4. **SDT のファインチューニング(M5 本丸)**。自分のサンプルで NVIDIA 機で追加学習し、スタイル参照 15 枚では拾いきれない癖を反映する。データは既存 JSON から SDT の (dx, dy, ペン状態) 形式への変換器を書けば作れる。
5. **生成結果の品質改善ループ**。SDT 出力が崩れた文字をライブラリ画面で確認して、崩れたものだけ自分で書き足す、という導線があると「よく使う文字から埋めていく」運用ができる。生成文字の一覧+「この字を書く」ボタン程度で始められる。

このうち 1 と 2 はローカルで完結し既存テストの延長で書けるので、実機やGPUが要る 3 と 4 より先に進めやすい。
